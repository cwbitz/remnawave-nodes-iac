# AGENTS.md

Ansible control node that manages the **Remnawave proxy Nodes** — the
`remnawave/node` containers a Remnawave Panel pushes Xray-core proxy
configuration to — on Debian-family VPSes, from a blank first boot: host
bootstrap, NetBird overlay join, host monitoring/security, the host firewall, then
the Remnawave Node. Idempotent and version-controlled.

This project owns **only the nodes**. The Remnawave Panel and the central
observability stack live in the sibling `docker-stack-iac` project and the NetBird
management server in `netbird-iac`; both are consumed strictly through their public
interfaces. Boundaries and scope are in `docs/components/panel-contract.md`.

Managed hosts live in the gitignored `inventory/hosts.yml` (committed template
`inventory/hosts.yml.example`, topology only) and are never hardcoded into docs,
roles, or templates; the project-owned baseline for every managed host (engine
range) is committed in `inventory/group_vars/all/main.yml`. Every host is in the
single `remnanodes` group — the play target
for every playbook. The shared SSH connection wiring lives in
`inventory/group_vars/all/main.yml`; every per-host knob (bootstrap, monitoring,
firewall, SSH hardening) lives in `inventory/host_vars/<hostname>/main.yml`.

`make deploy` is the one-shot entry point: it bootstraps every host in the
`remnanodes` group (one `playbooks/bootstrap.yml` run per host, stopping at the
first failure), then runs `playbooks/site.yml` (overlay join + monitoring, then
the Remnawave Node). `HOST=<name>` restricts the bootstrap to that node.

## Secrets and local-only files

- `inventory/host_vars/<hostname>/vault.yml` — **gitignored, never committed**
  (even encrypted). The single per-host vault holding the SSH identity values
  (`vault_host_root_*` / `vault_host_iac_*` / `vault_host_admin_*`), the NetBird
  setup key (`vault_netbird_setup_key`), the Remnawave node secret
  (`vault_remnanode_secret_key`) and the control-generated service-account
  passwords (`vault_host_iac_password`, and `vault_host_admin_password` only
  when `create_admin_account`). Schema reference:
  `inventory/host_vars/example/vault.yml.example`.
- Vault password file:
  `~/.config/projects/remnawave-nodes-iac/ansible_vault_password` (set in
  `ansible.cfg`; auto-generated by `make vault-init`). An encrypted vault cannot be
  read without it.
- A vault file must never stay plaintext: `write_vault` always encrypts, and a
  plaintext `vault.yml` is re-encrypted on the next write.

## Commands

- Control-node prerequisites: ansible-core within the supported range (pinned in
  `.tool-versions`, currently 2.19.x; asserted by the `playbooks/site.yml`
  preflight), Python 3, `openssl`, and the Galaxy collections in `requirements.yml`.
- `make install` — pinned toolchain (mise/asdf), Galaxy collections, `sshpass`,
  and Keychain 3. Keychain is a fallback ssh-agent used only when a configured
  private key has permissions OpenSSH rejects (e.g. WSL `/mnt/c`); every
  SSH-consuming target runs through `scripts/run-with-ssh-agent.sh`.
- `make vault-init` / `vault-view [HOST=]` / `vault-edit [HOST=]` — the vault
  password file and the per-host vault; `vault-view` covers every host (or one with
  HOST), and `vault-edit` targets HOST, or the single host when the inventory holds
  exactly one (a plaintext vault is encrypted first, and the keys are re-sorted
  alphabetically on save).
- `make host-init HOST=<name> [HOST_IP=] [HOST_PORT=]` — scaffold
  `inventory/hosts.yml` (from the committed `example/` when absent) and
  `inventory/host_vars/<name>/`, encrypt the scaffolded `vault.yml`, and ensure
  `<name>` exists under `remnanodes.hosts` in `inventory/hosts.yml`
  (idempotent; HOST defaults to `remnanode-1`). `HOST_IP`/`HOST_PORT` write that
  entry's `ansible_host`/`ansible_port`; an empty `HOST_IP` leaves the
  `CHANGE_ME_HOST_IP` placeholder the site preflight rejects, and a differing
  existing entry is only overwritten with `FORCE=1`. Files are rendered
  comment-free from the committed `example/` templates by
  `scripts/render_clean_template.py` (the scaffolded `vault.yml` also drops every
  blank line, via `--strip-blank-lines`); the inventory edit is line-based and
  comment-preserving (`scripts/ensure_inventory_host.py`).
- `make host-bootstrap [HOST=]` — refresh the host keys (`make hostkey-init`)
  and bootstrap one host; `make deploy` does the same for every node first (only
  `HOST` when set). When `HOST` is set the host-key refresh covers only that
  host and a scan failure is fatal; a full deploy downgrades a failed host key
  scan to a warning and updates the rest.
- `make agent` / `make monitoring` — the overlay join and the host
  monitoring/security parts (`make monitoring` joins the overlay first). The host
  firewall (`roles/firewall`), key-only SSH (`roles/sshd`) and the agent
  (`roles/agent`, `netbird_enabled`) are part of `site.yml`; `make deploy
  TAGS=firewall` / `TAGS=sshd` runs only one of them.
- `make dry-run` / `make deploy` — preview / one-shot deploy. The first
  `make dry-run` needs `make host-bootstrap` first (the `iac` account and its key
  must exist); check mode skips the overlay wait, so it also works before the
  first agent deployment.
- The internal `make lint` (`--syntax-check` + `ansible-lint` + `tests/knob_contract.yml` + `scripts/audit_example_knobs.py` +
  `scripts/check_host_keys.py`, `scripts/check_repo_privacy.py` and a `gitleaks`
  tree scan) is run by CI and hidden from `make help`. The audit keeps
  `host_vars/example/main.yml` a complete, value-accurate mirror of every
  operator knob; the contract playbook checks the schema against the role
  domains; the host-key guard rejects any tracked SSH host-key verification
  bypass; the privacy check rejects tracked local-only trees, credential files
  and real addresses or host names (allowlist in `.privacy-allowlist`), and CI
  repeats the gitleaks scan over the full history. `make test` runs the helper unit
  suite (`tests/`, pytest).
- `make print [HOST=]` — resolved host vars incl. decrypted vault.

## Important gotchas

- The deploy **requires the non-root service account**: `playbooks/site.yml`
  asserts `ssh_user != root` (override with `allow_root_login=true`).
- SSH hardening (`sshd_hardening_enabled`, `roles/sshd`) is **opt-in and
  self-protecting**: it closes password login, so it refuses to run unless the
  `iac` account has a public key and a key-only login is proven — and it
  reverts itself when a verification fails. Enable it only after
  `make host-bootstrap` has authorized the key.
- Host keys are refreshed before every bootstrap/deploy; a **changed** key is
  refused after printing its fingerprint — verify it out of band, then re-run
  `make hostkey-init FORCE=1`.
- Keep a node's `NODE_PORT` off the public internet — the Panel is the TLS client
  and reaches the node over the NetBird overlay (enable `firewall_enabled` so
  `roles/firewall` enforces it; see
  `docs/components/panel-contract.md`).
- The Remnawave Node image publishes version tags (e.g. `3.4.3`) as well as
  `latest`; `remnanode_version` is pinned to a version tag and Renovate tracks it.
  Never use `latest` — a moving tag makes a rollback impossible.
- Never commit a rendered `docker-compose.yml` (gitignored): it holds the live
  `SECRET_KEY`.

## Conventions

### Ansible: probe & bootstrap host targeting

Shared by the `*-iac` repos; keep this chain statically resolvable so
`--syntax-check` stays clean:

- **Control-node-only plays** (preflight, the SSH probe, `host_keys`,
  `ssh_agent_load`) use `hosts: localhost` + `connection: local` — never
  `hosts: all` + `connection: local`.
- **The action play that follows a probe** targets a host/group that resolves from
  the static inventory. Never target a dynamic-only group: it forces either an
  empty-group declaration in the inventory or a `--syntax-check` "Could not match
  supplied host pattern" warning.
- **Single-host bootstrap** targets the probed host **by name**, with a safe
  default —
  `hosts: "{{ bootstrap_host | default(groups['<group>'] | default([]) | first | default('', true)) }}"` —
  and `make <target> HOST=<name>` passes `-e bootstrap_host=<name>`.
- **Multi-host bootstrap** targets the real inventory group. `add_host` only
  injects the probed identity/vars onto a host already present in the inventory;
  it never creates a play target.
- **The probe must verify escalation, not just login.** An identity other than
  `root` is usable only when it can actually become root: proven with
  `sudo -n true` for the NOPASSWD `iac` account, while a password-sudo identity
  (`admin`) is proven with `sudo -S` before it is chosen. A
  half-provisioned account (login OK, sudoers not yet written) must never be
  chosen, or the bootstrap can no longer repair that host.

### Image version baseline

Every tag is a role constant in `roles/*/vars/`, each with a
`# renovate: datasource=docker depName=<image>` annotation (see `renovate.json`).

| Component | Registry | Version var |
|---|---|---|
| remnawave/node | dockerhub | `remnanode_version` (pinned version tag) |
| netbird-agent | ghcr.io | `netbird_agent_version` |
| alloy | dockerhub | `alloy_version` |

## Testing and verification

Two layers, and only one of them is executable:

- **Automated** — `make lint` (playbook syntax check, `ansible-lint`, the
  knob-schema/example audit, the host-key and repository-privacy checks,
  `gitleaks`) and `make test` (the helper suite under `tests/`). Both run in CI on
  every change.
- **Manual** — the cases that need a disposable host and destructive steps; they
  are a checklist in `docs/RUNBOOK.md` and are re-run when a role, the bootstrap
  or the backup path changes. `tests/` covers the helpers, not a live SSH session
  or a running stack.

### Environment and safety boundaries

- **Live hosts are read-only.** Inspect them with `make print`, `make print
  HOST=<name>`, `docker inspect`, `systemctl status` and external probes. No
  deploy, bootstrap, backup, restore or hardening run targets a live host.
- **Every state-changing or destructive case runs on a disposable Docker host**
  (systemd, Docker Engine with Compose v2, nftables, sshd) whose data can be thrown
  away; multi-host behaviour needs at least two of them.
- **Isolate the test environment**: its own inventory (never the real
  `inventory/hosts.yml`) and its own vault password file.
- **Ask before creating resources** — hosts, DNS records, storage paths — and
  before anything that costs money or touches a system outside the test host.
- **Order of work**: read-only checks first, then state-changing cases, then
  destructive ones; snapshot or back up before every destructive step.
- **Never print, paste or commit secrets.** Redact evidence before quoting it; a
  secret in a log or a report is itself a defect to record.

### Execution rules

- Write the expected result before running a case; never backfill it.
- Cases are independently runnable; declare prerequisites where order matters.
- A defect gets a reproducing case before anything else happens.
- Separate product defects from environment failures, and state the evidence for
  that call.
- Skip only with a recorded reason; never count an unexecuted case as a pass.
- No change to the product to make a case pass; no drive-by fixes.

### Recording and defects

- Keep raw logs, `-vvv` output, `docker inspect`, `systemctl status` and probe
  responses under `/tmp/opencode/test-run-<UTC stamp>/artifacts/<case>/`; never
  store a decrypted vault, and redact before quoting.
- Severity: `blocker` (data loss, outage, security), `major` (feature unusable, or
  docs contradict behaviour), `minor`, `nit`. Each entry carries a minimal
  reproduction, expected vs actual, impact, evidence path and a suggested fix;
  merge entries that share a root cause.

### Definition of done

- `make lint` and `make test` green;
- the manual checklist passes on the disposable host, and a second run at the
  same desired state reports `changed=0` outside the documented non-idempotent
  steps;
- every destructive path fails safely with an actionable message;
- no unexplained high-severity security finding;
- every conclusion points at evidence, and every unexecuted check names the
  reason and what would unblock it.
