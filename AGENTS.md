# AGENTS.md

Ansible control node that manages the **Remnawave proxy Nodes** — the
`remnawave/node` containers a Remnawave Panel pushes Xray-core proxy
configuration to — on Debian-family VPSes, from a blank first boot: host
bootstrap, NetBird overlay join, host monitoring/security, the host firewall, then
the Remnawave Node. Idempotent and version-controlled.

This project owns **only the nodes**. The Remnawave Panel and the central
observability stack live in the sibling `docker-stack-iac` project and the NetBird
management server in `netbird-iac`; both are consumed strictly through their public
interfaces. Boundaries and scope are in `docs/components/panel-contract.md`.

Managed hosts live in the gitignored `inventory/hosts.yml` (committed template
`inventory/hosts.yml.example`, topology only) and are never hardcoded into docs,
roles, or templates; the project-owned baseline for every managed host (engine
range) is committed in `inventory/group_vars/all/main.yml`. Every host is in the
single `remnanodes` group — the play target
for every playbook — whose `group_vars/remnanodes/main.yml` holds the shared
SSH connection wiring plus `install_docker`, `host_admin_enabled`,
`monitoring_enabled` and `host_firewall_enabled`; per-host, non-secret settings
live in `inventory/host_vars/<hostname>/main.yml`.

`make deploy` is the one-shot entry point: it bootstraps the host, then runs
`playbooks/site.yml` (overlay join + monitoring, then the Remnawave Node).

## Secrets and local-only files

- `inventory/host_vars/<hostname>/vault.yml` — **gitignored, never committed**
  (even encrypted). The single per-host vault holding the SSH identity values
  (`vault_host_root_*` / `vault_host_ansible_*` / `vault_host_admin_*`), the NetBird
  setup key (`vault_netbird_setup_key`), the Remnawave node secret
  (`vault_remnanode_secret_key`) and the control-generated service-account
  passwords (`vault_host_ansible_password`, and `vault_host_admin_password` only
  when `host_admin_enabled`). Schema reference:
  `inventory/host_vars/example/vault.yml.example`.
- Vault password file:
  `~/.config/projects/remnawave-nodes-iac/ansible_vault_password` (set in
  `ansible.cfg`; auto-generated by `make vault-init`). An encrypted vault cannot be
  read without it.
- A vault file must never stay plaintext: `write_vault` always encrypts, and a
  plaintext `vault.yml` is re-encrypted on the next write.

## Commands

- Control-node prerequisites: ansible-core within the supported range (pinned in
  `.tool-versions`, currently 2.19.x; asserted by the `playbooks/site.yml`
  preflight), Python 3, `openssl`, and the Galaxy collections in `requirements.yml`.
- `make install` — pinned toolchain (mise/asdf), Galaxy collections, `sshpass`,
  and Keychain 3. Keychain is a fallback ssh-agent used only when a configured
  private key has permissions OpenSSH rejects (e.g. WSL `/mnt/c`); every
  SSH-consuming target runs through `scripts/run-with-ssh-agent.sh`.
- `make vault-init` / `vault-view [HOST=]` / `vault-edit [HOST=]` — the vault
  password file and the per-host vault; `vault-view` covers every host (or one with
  HOST), and `vault-edit` targets HOST, or the single host when the inventory holds
  exactly one.
- `make host-init HOST=<name> [HOST_IP=] [HOST_PORT=]` — scaffold
  `inventory/hosts.yml` (from the committed `example/` when absent) and
  `inventory/host_vars/<name>/`, encrypt the scaffolded `vault.yml`, and ensure
  `<name>` exists under `remnanodes.hosts` in `inventory/hosts.yml`
  (idempotent; HOST defaults to `remnanode-1`). `HOST_IP`/`HOST_PORT` write that
  entry's `ansible_host`/`ansible_port`; an empty `HOST_IP` leaves the
  `CHANGE_ME_HOST_IP` placeholder the site preflight rejects, and a differing
  existing entry is only overwritten with `FORCE_IP=1`. Files are rendered
  comment-free from the committed `example/` templates by
  `scripts/render_clean_template.py`; the inventory edit is line-based and
  comment-preserving (`scripts/ensure_inventory_host.py`).
- `make host-bootstrap [HOST=]` — bootstrap one host; `make deploy` runs it first.
- `make agent` / `make monitoring` — the overlay join and the host
  monitoring/security parts. The host firewall (`roles/firewall`) is part of
  `site.yml`; `make deploy TAGS=firewall` runs only it.
- `make dry-run` / `make deploy` — preview / one-shot deploy.
- The internal `make lint` (`--syntax-check` + `ansible-lint`) is run by CI and
  hidden from `make help`.
- `make print [HOST=]` — resolved host vars incl. decrypted vault.

## Important gotchas

- The deploy **requires the non-root service account**: `playbooks/site.yml`
  asserts `host_ssh_user != root` (override with `host_allow_root_login=true`).
- Keep a node's `NODE_PORT` off the public internet — the Panel is the TLS client
  and reaches the node over the NetBird overlay (`roles/firewall` enforces it; see
  `docs/components/panel-contract.md`).
- The Remnawave Node image only publishes moving tags (`latest` / `sha-*`), so
  `remnanode_version` cannot be pinned; Renovate tracks it for manual review.
- Never commit a rendered `docker-compose.yml` (gitignored): it holds the live
  `SECRET_KEY`.

## Conventions

### Ansible: probe & bootstrap host targeting

Shared by the `*-iac` repos; keep this chain statically resolvable so
`--syntax-check` stays clean:

- **Control-node-only plays** (preflight, the SSH probe, `host_keys`,
  `ssh_agent_load`) use `hosts: localhost` + `connection: local` — never
  `hosts: all` + `connection: local`.
- **The action play that follows a probe** targets a host/group that resolves from
  the static inventory. Never target a dynamic-only group: it forces either an
  empty-group declaration in the inventory or a `--syntax-check` "Could not match
  supplied host pattern" warning.
- **Single-host bootstrap** targets the probed host **by name**, with a safe
  default —
  `hosts: "{{ bootstrap_host | default(groups['<group>'] | default([]) | first | default('', true)) }}"` —
  and `make <target> HOST=<name>` passes `-e bootstrap_host=<name>`.
- **Multi-host bootstrap** targets the real inventory group. `add_host` only
  injects the probed identity/vars onto a host already present in the inventory;
  it never creates a play target.
- **The probe must verify escalation, not just login.** An identity other than
  `root` is usable only when it can actually become root: proven with
  `sudo -n true` for a password-less (NOPASSWD) identity, while a password-sudo
  identity proves it at deploy time via `ansible_become_password`. A
  half-provisioned account (login OK, sudoers not yet written) must never be
  chosen, or the bootstrap can no longer repair that host.

### Image version baseline

Every tag is rendered through role-default vars, each with a
`# renovate: datasource=docker depName=<image>` annotation (see `renovate.json`).

| Component | Registry | Version var |
|---|---|---|
| remnawave/node | dockerhub | `remnanode_version` (upstream has no pinned tags) |
| netbird-agent | ghcr.io | `netbird_agent_version` |
| alloy | dockerhub | `alloy_version` |
